# kai-product

Pre-release / in progress source. This package is not part of the default marketplace surface; see [package availability](../../docs/reference/package-availability.md).

Product discovery, scope, evidence, analytics, and product-led growth over kai-core.

The supported baseline is **kai-core plus kai-product**. Supply product/user
evidence, research, exports, plans or an authorized surface directly. A bounded
answer needs no invented initiative, work item, sibling installation or producer
call. Missing facts remain explicit limits. Creative owns UI/brand design;
engineering owns implementation. Naming a later owner does not perform its work.

This is inspected source and emitted install metadata, not a published release
or a live-host compatibility claim. The current checkout prepares `9.0.0`;
install/update commands require a source containing this refactor.

## State, closure and independence

Eager inheritance, managed guards, bulk-load prose and retired core IDs are
removed from all ten roles. Each probes core before its first shared rule,
states a role-specific response-only fallback and forbids coordinated `.kai`
state without core. Contracts load at the actual workspace, acting, record,
proposal, peer, artifact or closure action, not from a shared context manifest.

Existing coordinated work preserves holder/token/version checks before writes,
touch/dependency checks, collision stops, evidence, next role, lease and HANDOFF.
Only an authorized sole worker may self-grant an existing item; a steward's
promotion/waiver does not make it the director. Activity signals never prove
completion. Personas report evidence without lifecycle/acceptance authority.

Artifacts keep the existing private product/QA run paths and initiative targets.
Raw/customer/health data, browser state and screenshots stay private; only
sanitized text is eligible for deliberate publication. Durable completion
requires scope, grounding, named independent exact-revision acceptance and
disposition, plus validity ownership/revalidation. Unaccepted output remains
provisional. `completed` knowledge is not a launched or shipped product.

PM initiative closure proves **work, asset, backlog, ownership and outcome**
sweeps, typed milestone terminal states, exact summary/deliverable paths and
ACTIVE/index/log updates. Archival explicitly maintains, carries, freezes,
supersedes, retracts or discards eligible assets without moving publications.

Assessors write findings, never repair the reviewed target or launder patches
through another role. Fitness cross-domain judgments require a real supplied
assessment or actual peer; the old simulated consult/best-guess option is
removed. An unavailable judgment limits that conclusion, not all supported
findings. Test-profile state changes, paid generation and destructive actions
require explicit consent; automatic localStorage resets are removed.

Fitness numerical benchmarks remain source-bound audit prompts, not universal
prescriptions. Missing standards/portion data are evidence gaps. Screening
cannot be reduced to age/BMI-only clearance or a blanket soft warning for
concerning symptoms. No clinical efficacy or guideline-currency validation was
performed during this source refactor.
