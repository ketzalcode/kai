# README pattern

Use this pattern for a repository or product landing page. A README is a front
door, not a release archive, design specification, or complete reference.

## Reader journey

1. **Name and outcome** — what the project is and what problem it solves.
2. **Why it matters** — the shortest evidence-backed value statement.
3. **First success** — the smallest working example or path.
4. **Installation** — prerequisites and commands needed for that first success.
5. **Common use** — representative tasks, not every feature.
6. **Deeper paths** — links to concepts, reference, operations, contributing,
   support, and security where those pages exist.
7. **Current status** — brief supported versions or maturity, with history
   delegated to the changelog.

## Checks

- The first screenful answers what, why, and where to start.
- Installation commands and the first example work from a clean environment.
- The README does not duplicate details owned by deeper documentation.
- Status describes the present release rather than narrating release history.
- Links, badges, screenshots, and commands are current and accessible.
- Internal architecture appears only when needed to choose or start using the
  project.
