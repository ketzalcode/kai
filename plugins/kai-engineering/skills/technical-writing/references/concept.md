# Concept pattern

Use this pattern when the reader needs a mental model rather than a procedure or
lookup table.

## Structure

1. **Question** — the concept this page helps the reader understand.
2. **Mental model** — the simplest accurate explanation.
3. **Boundaries** — what belongs inside the concept and what does not.
4. **Relationships** — how the parts interact; add one diagram when it reduces
   explanation cost.
5. **Consequences** — why the model changes implementation or operational
   choices.
6. **Examples and counterexamples** — concrete cases that clarify the boundary.
7. **Related tasks and reference** — links to action and lookup pages.

## Checks

- The explanation starts from the reader's likely prior knowledge.
- Each section introduces one main idea.
- Analogies clarify without replacing the real technical model.
- Diagrams and prose agree.
- Implementation detail appears only when it explains the concept.
