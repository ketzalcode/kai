**Operator-approved decisions carried into this north star** (all grounded in
the committed proposal and the code already landed in the monolith; they
incorporate the corrections recorded in the proposal's "Revised while executing
it" notes from the prior intake review):

- Core is required, never optional, never in the selector.
- The degraded-mode block is a refusal, not a fallback contract — so it cannot
  drift from core.
- Core skills carry the owned-namespace `kai-core-*` prefix. **Corrected** from
  an earlier draft that versioned every core skill name (`-v1` on all 22): that
  was measured wrong — it makes every contract bump a rename of ~1,000 mentions.
  The prefix alone removes the collision; exactly one skill is version-pinned,
  `kai-core-contract-v1`, the preflight probe.
- **No taxonomy segment in skill names** — classification is the most volatile
  attribute and the name is the most expensive place to keep it; it lives in
  frontmatter and groups the generated catalog instead.
- Availability logic tests **membership** of the read roster, never a
  model-computed count (the same call that listed all 56 ids reported COUNT=55
  and COUNT=53 on separate runs). A director resolves availability **before** it
  takes a lease; the gap is reported, never written into the item as `blocked`.
- The monolith stays authoritative until each pack's guarantees pass; move one
  department at a time, never 56 agents in one PR.
- `1.0.0` is reserved for the split; all groundwork ships on `0.x`.

**Drafted:** thin core (mission, vision, scope, seven non-negotiable
principles), four success measures, and four milestones — `partition-lock`,
`dependency-guarantees`, `first-pack-extracted`, `five-pack-split-shipped`.
Each milestone's `required_items` is empty pending steward-accepted
decomposition.

**Seeded:** one `proposed`, docs-only planning item,
