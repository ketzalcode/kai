## The degraded-mode refusal

> If `kai-core` is unavailable, I answer one localization question against the
> surface or build in front of me — a single readiness or locale-QA observation
> — and stop before any routed workflow; I create no `.kai` state, claim no
> readiness item, and record no Kai activity; and I tell the operator to install
> or update `kai-core` before I run a coordinated localization pass.

- **Fact 1** — direct single-shot work only: *"one localization question … a
  single readiness or locale-QA observation — and stop before any routed
  workflow."*
- **Fact 2** — no state, no claimed item, no reported activity: *"I create no
  `.kai` state, claim no readiness item, and record no Kai activity."*
- **Fact 3** — operator installs/updates core: *"I tell the operator to install
  or update `kai-core`."*

The refusal derives from this workflow's degraded product: a single
readiness-or-locale-QA observation on the surface in front of it that stops
before the multi-step routed pass, because the routed localization procedure is
the coordinated behaviour that is unavailable.
