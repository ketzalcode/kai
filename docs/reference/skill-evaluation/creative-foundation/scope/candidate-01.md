This expands scope, not current screen work. It adds a new persistent surface and a multi-result workflow, so treat it as a proposal rather than folding it into the Search Results page work today.

PROPOSAL
  problem: Operators have to open similar results in separate tabs to compare them.
  proposed_change: Add a persistent comparison tray that lets them pin up to three results and compare them side by side from the Search Results page.
  friction_cost: Adds a new pinned-results surface, pin/unpin controls on each row, tray state management, and a new side-by-side comparison interaction.
  mission_tradeoff: Improves comparison efficiency, but it introduces new UI and workflow complexity beyond the current filter/sort/save/open surface, so it should not be absorbed into the present scope.
  scope_target: Search Results page enhancement / future comparison workflow proposal.
