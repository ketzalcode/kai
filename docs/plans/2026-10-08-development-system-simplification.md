# Kai Development System Simplification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Kai's migration-heavy, prose-validated, per-PR development system with a current-schema-only fast-ship workflow, one Linux nightly, exact-SHA Monday releases, and a small behavioral test suite.

**Architecture:** Keep the schema-5 product boundaries while deleting historical compatibility and duplicate contract authorities. Repository instructions establish the human workflow; structured JavaScript/JSON declarations own executable facts; one build boundary generates consumer and release artifacts; local targeted tests plus one Linux nightly provide confidence.

**Tech Stack:** Native ESM on Node 24, `node:test`, `node:sqlite`, esbuild, GitHub Actions, GitHub CLI, JSON and Markdown plugin assets.

**Spec:** `docs/designs/development-system-simplification.md`

## Global Constraints

- Ship only `kai-core`, `kai-engineering`, and `kai-creative`.
- Support only workspace schema 5; do not decode or migrate historical records.
- Preserve `.kai/` privacy and `docs/kai/` accepted-publication separation.
- Preserve path traversal, containment, link, and namespace safety.
- Preserve SQLite authority, Direction binding, work hierarchy, leases, versions, and subject isolation.
- Generated consumers must run without checkout dependencies.
- Run no `pull_request` or `push` CI.
- Run one Linux/Node 24 nightly at 05:00 UTC.
- Release Mondays at 08:00 UTC only from the exact green nightly SHA.
- `package.json` is the edited version authority.
- Validation agreement: **Lean** - TDD for changed logic, targeted tests, the fast smoke suite, and build checks only when relevant.
- Final targets: `npm test` at most 60 seconds, nightly at most five minutes, at most 15 test entrypoints, at most 8,000 test lines, and at most 30 pack-preview assertions.
- Use ASCII in source and generated text unless an existing contract requires otherwise.
- Do not preserve deprecated files solely for history; Git history is the archive.
- Do not stage or commit a consumer repository's `AGENTS.md` during onboarding.

- [ ] **Step 3: Implement pure release decisions**

Implement in `tools/lib/release.mjs`:

```js
const SEMVER = /^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)(?:-([0-9A-Za-z.-]+))?$/;

export const BEHAVIOR_PREFIXES = Object.freeze([
  'plugins/', 'src/', 'tools/',
]);

export const BEHAVIOR_FILES = new Set([
  'package.json',
  'package-lock.json',
  'plugin.json',
  '.github/plugin/marketplace.json',
]);

export function isBehaviorPath(value) {
  const path = value.replace(/\\/g, '/');
  return BEHAVIOR_FILES.has(path)
    || BEHAVIOR_PREFIXES.some(prefix => path.startsWith(prefix));
}

export function parseSemver(version) {
  const match = SEMVER.exec(version ?? '');
  return match
    ? {core: match.slice(1, 4).map(Number), prerelease: match[4] ?? null}
    : null;
}

export function isForwardVersion(latestVersion, currentVersion) {
  const latest = parseSemver(latestVersion);
  const current = parseSemver(currentVersion);
  if (!current) return false;
  if (!latest) return true;
  for (let index = 0; index < 3; index += 1) {
    if (latest.core[index] !== current.core[index]) {
      return current.core[index] > latest.core[index];
    }
  }
  return Boolean(latest.prerelease && !current.prerelease);
}

export function generatedVersionErrors(currentVersion, generatedVersions) {
  return Object.entries(generatedVersions)
    .filter(([, version]) => version !== currentVersion)
    .map(([file, version]) => `${file} has ${version}; expected ${currentVersion}`);
}

export function extractReleaseNotes(changelog, version) {
  const lines = changelog.replace(/\r\n/g, '\n').split('\n');
  const start = lines.findIndex(line => line.startsWith(`## [${version}]`));
  if (start === -1) throw new Error(`CHANGELOG.md has no ${version} section`);
  const next = lines.findIndex((line, index) => index > start && /^## \[/.test(line));
  return lines.slice(start + 1, next === -1 ? lines.length : next).join('\n').trim();
}

export function evaluateReleaseReadiness(input) {
  const behaviorChanged = input.changedFiles.some(isBehaviorPath);
  if (!behaviorChanged) {
    return {ok: true, release: false, reason: 'no-release-needed', errors: [], notes: ''};
  }
  const errors = [];
  if (!isForwardVersion(input.latestVersion, input.currentVersion)) {
    errors.push(`behavior changed without a forward version: ${input.latestVersion} -> ${input.currentVersion}`);
  }
  let notes = '';
  try {
    notes = extractReleaseNotes(input.changelog, input.currentVersion);
  } catch (error) {
    errors.push(error.message);
  }
  errors.push(...generatedVersionErrors(input.currentVersion, input.generatedVersions));
  return {
    ok: errors.length === 0,
    release: errors.length === 0,
    reason: errors.length === 0 ? 'ready' : 'not-ready',
    errors,
    notes,
  };
}
```

Keep filesystem and Git access out of this module.

```yaml
name: weekly-release

on:
  schedule:
    - cron: '0 8 * * 1'
  workflow_dispatch:

permissions:
  actions: read
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    env:
      GH_TOKEN: ${{ github.token }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Require exact green nightly SHA
        shell: bash
        run: |
          current="$(git rev-parse HEAD)"
          nightly="$(gh run list --workflow nightly.yml --branch main --status success \
            --limit 1 --json headSha --jq '.[0].headSha // ""')"
          test -n "$nightly"
          test "$current" = "$nightly"
      - name: Read release version
        id: version
        shell: bash
        run: echo "value=$(node -p "require('./package.json').version")" >> "$GITHUB_OUTPUT"
      - name: Skip an existing tag
        shell: bash
        run: test -z "$(git tag -l "v${{ steps.version.outputs.value }}")"
      - name: Verify release readiness
        run: npm run release-readiness -- --json
      - name: Extract release notes
        run: npm run release-notes -- --version "${{ steps.version.outputs.value }}" > release-notes.md
      - name: Create tag and release
        run: gh release create "v${{ steps.version.outputs.value }}" --target "$GITHUB_SHA" --title "v${{ steps.version.outputs.value }}" --notes-file release-notes.md
```

The existing-tag step intentionally exits nonzero and marks the scheduled run
skipped only if implemented through a preceding output/conditional. During
implementation, use an `id: tag` step that writes `exists=true|false`, then put
`if: steps.tag.outputs.exists == 'false'` on readiness, notes, and release
steps. Do not make an already released version a failed workflow.
